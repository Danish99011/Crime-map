# Open Data Portals, APIs and Aggregators

_Agent: open-data-portals · Researched: 2026-09-19 · Entries: 1 VERIFIED_LIVE / 22 CITED / 4 UNVERIFIED · 27 total_

> **Environment caveat that shapes this whole dossier.** This session's egress proxy blocks
> every `*.gov.in` host (`data.gov.in`, `api.data.gov.in`, `ndap.niti.gov.in`,
> `smartcities.data.gov.in`, `apisetu.gov.in`), plus `data.opencity.in`, `dataful.in`,
> `justicehub.in`, `kaggle.com`, `huggingface.co`, `dateno.io` and `web.archive.org`.
> Reachable: `github.com`, `raw.githubusercontent.com`, `en.wikipedia.org`. The session's
> WebSearch budget (200 calls) was exhausted by sibling agents partway through.
> **I therefore verified data.gov.in by a different route: I downloaded and parsed
> data.gov.in's own catalogue metadata (198,428 resources, resource IDs + titles + column
> lists) from the mirror shipped with the official-ish `datagovindia` API client.** Every
> resource ID below is a real string from that catalogue, not a guess. What I could *not*
> do is call `api.data.gov.in` and see rows come back. Entries are labelled accordingly.

## Executive summary

- **data.gov.in is the only crime source in this domain with a real, documented, free REST
  API**, and it holds far more NCRB material than its search UI suggests: **2,521 resources
  under NCRB organisations**, of which **~1,167 have a crime word in the title**.
  Endpoint: `https://api.data.gov.in/resource/{resource_id}?api-key={key}&format=json`.
- **The granularity ceiling on data.gov.in is district, and district coverage is thin and old.**
  Of 2,521 NCRB resources: **1,299 state-level, 593 city/metropolitan, 23 district-level, 0
  police-station.** I grepped all 198,428 resources for a `police_station` column: 31 hits,
  none of them crime counts (they are seizure tables and Rajya Sabha answers).
- **The genuinely useful spine is the metropolitan-cities series, not the district series.**
  509 city-level NCRB crime resources, covering 19 (print) to 53 (web) cities with population
  >2M, crime-head × city, 2015–2021. `City and Crime Head-wise IPC Crimes during 2019`
  (`bd01039b89574157b34d70e3968a9c95`) has **426 columns** — the full IPC head breakdown.
- **State open-data portals are a dead end for crime.** The federated state sub-portals on
  data.gov.in (`tn.data.gov.in`, 928 resources) contain essentially no crime data. The single
  exception is a **Karnataka State Police "Crime Review for the month of …" monthly series for
  2022** (6 resources) — the only *monthly* crime feed anywhere in the open-data layer.
- **Smart Cities portal is a disappointment.** 242 resources in the catalogue index, of which
  **12** touch crime/safety, all city-level annual snapshots 2014–2019, most already stale when
  published. **No ICCC feeds, no emergency-response data, no incident-level anything.**
- **OpenCity (`data.opencity.in`) is the best aggregator in India for this project** — a CKAN
  instance run by Civic Insights Foundation that mirrors NCRB *Crime in India* tables as CSVs
  and, crucially, carries **Karnataka State Police crime data for 2022–2025** and a
  **`police-jurisdiction-maps-for-major-cities-of-india`** dataset. That last one may be the
  single most valuable geometry asset for a police.uk-style map in India.
- **Dataful (Factly) has good provenance discipline.** Citations in the wild take the form
  *"National Crime Record Bureau. Cyber Crimes from NCRB – Master Data: Year- and State-wise
  Types of Cyber Crimes committed in Violation of IT Act [Data set]. Dataful.
  https://dataful.in/datasets/19643"* — i.e. it names the originating NCRB table. CSV/XLSX/
  **Parquet**. Download may require sign-in. Licence unstated on the pages I could reach.
- **NDAP's geography harmonisation is real and valuable; its API is not production-grade.**
  Its API emits `DistrictName,DistrictCode` (LGD codes) as first-class dimensions — that *would*
  save us months. But the key is a per-dataset encrypted blob generated by hand from the
  dataset page, it expires (401/403), the only host seen in the wild is `loadqa.ndapapi.com`
  (a **QA** host), and Google's Data Commons link-checker recorded `ndap.niti.gov.in/dataset/7300`
  and `/7375` as **404** and `/info?tab=termsandconditions` as **404**. Harvest the crosswalk;
  do not build the pipeline on it.
- **Kaggle is roughly half poison.** `umeshchandra789/crimes-in-india` ships a file literally
  named `Crimes_in_india_2001-2023_synthetic.csv`. `sudhanvahg/indian-crimes-dataset` cites no
  government source at all. Only `rajanand/crime-in-india` (NCRB-derived, 2001–2022, 75+ CSVs)
  is defensible, and only as a convenience copy of data we should pull from NCRB ourselves.
- **Finest spatial granularity achievable in this domain: `city` (metropolitan city totals by
  crime head), with `district` available only for 2001–2015.** Nothing here gets us to a
  street, a ward or a beat. The map's fine-grained layer must come from another agent's domain
  (state police CCTNS/FIR portals); this domain supplies the backbone and the benchmark.

## Source entries

### 1. data.gov.in — Open Government Data (OGD) Platform India, Resource API

The platform of record. Every published resource gets a REST endpoint. Verified pattern
(consistent across four independent sources: the `datagovindia` R and Python clients, the
PublicAPIs.io listing, and the Apify connector):

```
id: open-data-portals-datagovin-api
publisher: NIC / DIC, Ministry of Electronics & IT (MeitY)
endpoint: https://api.data.gov.in/resource/{resource_id}?api-key={KEY}&format=json&offset=0&limit=10
params: api-key (required) · format=json|xml|csv · offset · limit · filters[<Field>]=<value>
        · fields=a,b,c · sort[<Field>]=asc|desc
response: {"status":"ok","total":N,"count":n,"limit":..,"offset":..,"fields":[..],"records":[..]}
api key: free, self-registered at data.gov.in (profile → generate API key). A shared sample
         key exists and is heavily throttled — register your own before any real pull.
rate limit: no published limit. Clients in the wild implement capped backoff on 429/5xx,
         which means 429s do occur in practice.
docs: https://data.gov.in/help/how-use-datasetapi · API listing: https://www.data.gov.in/apis
licence: NDSAP (National Data Sharing and Accessibility Policy) → GODL-India
gotcha: resource IDs circulate in TWO forms — 32-hex undashed (as stored in the catalogue,
        e.g. 7ac0fd4f0aa34600a7729f5b8c6524f8) and dashed UUID. Normalise both.
gotcha: filters[] field names are CASE-SENSITIVE. filters[State] works, filters[state] silently
        returns zero rows. Always probe with limit=1 before building a pagination loop.
verification: CITED (endpoint pattern corroborated 4x; could not call it — host egress-blocked)
```

### 9. NDAP — National Data & Analytics Platform (NITI Aayog)

**Verdict: harvest the geography crosswalk, do not build the pipeline on it.**

```
id: open-data-portals-ndap
landing: https://ndap.niti.gov.in/ · dataset pages: https://ndap.niti.gov.in/dataset/{id}
api (observed in the wild, not officially documented):
  https://loadqa.ndapapi.com/v1/openapi?API_Key={encrypted_blob}&ind=I{ds}_{n},I{ds}_{n}…
    &dim=Country,StateName,StateCode,DistrictName,DistrictCode,Year[,TRU,…]&pageno=1
auth: the API_Key is a long Fernet-style encrypted blob GENERATED PER DATASET from that
      dataset's page. It is not an account key. It expires.
```
What is genuinely good: the `dim=` list. NDAP exposes **`StateCode` and `DistrictCode`
(LGD codes) as first-class dimensions alongside names**, plus `TRU` (rural/urban). That is
exactly the harmonisation layer a crime map needs, and building it ourselves from NCRB's
free-text district names is weeks of work. **Recommendation: pull NDAP's district
name↔LGD-code crosswalk once, store it, and use it to normalise NCRB district strings.**

What is bad, and disqualifying for a production feed:
- The only host anyone uses is **`loadqa.ndapapi.com`** — a *QA* hostname. Five independent
  repos, including **Google's `datacommonsorg/data`**, call the QA host. There is no evidence
  of a stable production host.
- Google's own import README documents the failure mode: *"If the download script fails or logs
  HTTP 401 Unauthorized / 403 Forbidden errors: 1. Obtain Fresh API Query/Key — navigate to
  NDAP Dataset 7300, generate or copy the updated API query URL…"* **A pipeline that requires a
  human to visit a web page and copy a token is not a pipeline.**
- `datacommonsorg/schema`'s link-checker (`test/url_allowlist.csv`) records
  `https://ndap.niti.gov.in/dataset/7300` → **404**, `…/dataset/7375` → **404**, and
  `https://ndap.niti.gov.in/info?tab=termsandconditions` → **404**. Dataset IDs churn, and
  **the terms-and-conditions page is missing**, so the licence is effectively unstated.
- Crime holdings: I could not enumerate them. A third-party resource inventory lists
  *"NITI NDAP — Crime in India: IPC Statistics"* as a real NDAP dataset but marks it
  `UNVERIFIED`, and notes "State-level, not always district". **Assume NDAP's NCRB holdings are
  state-level annual, i.e. no better than data.gov.in.**

**Provenance: good but not perfect.** OpenCity states the upstream source per dataset
(`bcp.karnataka.gov.in`, `ksp.karnataka.gov.in`, `ncrb.gov.in`) — that is the right behaviour.
**Licence is the weak point:** mirrors carry *"Other (Public Domain)"* or *"No License Provided"*,
which is OpenCity's assertion about someone else's data, not the original publisher's grant.
For a public-facing safety product, **re-derive the licence from the original publisher and cite
the original, using OpenCity only as the transport.**

### 19–21. Kaggle — mostly unusable, and dangerously so

| dataset | verdict |
|---|---|
| `kaggle.com/datasets/rajanand/crime-in-india` | **Usable with care.** Described as state-wise 2001–2022, 75+ CSVs, NCRB-derived. The de-facto standard copy in the Indian data community. Still a mirror with no checksum against NCRB. |
| `kaggle.com/datasets/aayushrokade/crime-review-of-karnataka-2021-2024` | Derived from KSP Monthly Crime Review PDFs. Plausible but re-derive from KSP yourself. |

"Indian crime" CSVs with 16k rows and plausible timestamps are circulating freely and are being
loaded into public-facing "crime map" and "safe route" apps. If any of it reaches our pipeline
we will be publishing fabricated risk scores for real neighbourhoods. **Rule for Phase 2: no
dataset enters the pipeline without a resolvable link to a government table.**

### 23. api.data.gov.in vs apisetu.gov.in

Two different things, and only one is a data source.
- **api.data.gov.in** — the *dataset* API described in entry 1. This is ours.
- **apisetu.gov.in** — MeitY's **API exchange / gateway** for *transactional* government APIs
  (DigiLocker document pull, ABHA health ID, PM-JAY verification, CoWIN). Directory:
  `https://directory.apisetu.gov.in/api-collection/digilocker`; DigiLocker issuer spec:
  `https://cf-media.api-setu.in/resources/DigiLocker-Issuer-APISpecification-v1-13.pdf`.
  **There is no crime or FIR API on API Setu that I found any evidence for**, and there
  shouldn't be — it is an identity/document exchange, gated per-consumer with OAuth2 and
  onboarding paperwork. **India Stack / DigiLocker are not relevant to this project.** Record
  the negative and move on.

## Granularity reality check

| Level | Available? | Source | Years | Refresh | Honest note |
|---|---|---|---|---|---|
| `address` / `point` | **No** | — | — | — | Nothing in the open-data layer. Not one row. |
| `beat` / `ward` | **No** | — | — | — | Ward *boundaries* exist (OpenCity, DataMeet); ward *crime counts* do not. |
| `police-station` | **No (counts)** / partial (geometry) | OpenCity `police-jurisdiction-maps-for-major-cities-of-india`, `bengaluru-city-police-contact-info` | station lists 2012, contacts 2025 | irregular | **31 of 198,428 data.gov.in resources have a `police_station` column and none are crime counts.** We can draw the polygons; we cannot fill them from this domain. |
| `city` | **Yes — best available** | NCRB metro-city series on data.gov.in | 2015–2021 (incidence to 2019; disposal/arrests to 2021) | annual, 12–21 month lag | 19 cities in print, 53 on the web. City = *commissionerate*, not municipal boundary. |
| `district` | **Yes, but frozen** | data.gov.in district IPC/women series | IPC 2013–2014; women 2001–2015; archival 1973/1985/1998 | **stopped** | The map-shaped table ends in 2014. This is the central disappointment of the domain. |
| `state` | Yes, abundant | 1,299 NCRB state resources; Dataful; NDAP | 1970–2021 (open data), to 2023 via OpenCity/Dataful mirrors | annual | Backbone and benchmark only. |
| monthly, any level | **One feed** | Karnataka Police Computer Wing, 2022 | Jan–Jul 2022 (May missing) | monthly, then stopped | State totals by crime head. Proof it *can* be done; not proof it *is* being done. |

**The gap, stated plainly:** the product wants "is this street safe tonight". This domain
delivers "this city of 8 million registered N murders in 2019". The open-data layer cannot
build a police.uk clone. It can build the national/city benchmark that a finer-grained
per-city feed is validated against — and it can supply the police-jurisdiction geometry that a
finer feed would be joined onto.

## Blockers and how to get past them

1. **Everything worth having is behind a `.gov.in` host that this environment cannot reach.**
   Not a property of the data — a property of this session. A human in India, or any runner
   with normal egress, hits none of this. *Action: re-run the verification pass from an
   unrestricted network; every resource ID in this dossier is then a one-line `curl` away.*
2. **The catalogue index is a Sept-2023 snapshot.** It cannot contain NCRB 2022 or 2023.
   *Action: first Phase-2 job is a fresh catalogue sync — page `api.data.gov.in` for all
   NCRB-org resources and diff against `idx_maps.gz`. Budget for 429s.*
3. **District-level crime stops in 2014/2015.** No workaround inside this domain. *Action:
   district-level 2015+ must come from parsing NCRB PDF volumes (another agent's domain) or
   from state police CCTNS portals. Use the 2001–2014 open series purely to validate whatever
   PDF parser gets built, since the same years exist in both forms.*
4. **NDAP's key cannot be automated.** *Action: treat NDAP as a one-off manual pull. Get the
   district↔LGD-code crosswalk and the NCRB "Crime in India: IPC Statistics" dataset by hand,
   snapshot them into our repo with the retrieval date, and never depend on the API again.*
5. **Licence is unstated more often than it is stated.** data.gov.in resources are GODL-India
   via NDSAP — that one is clean. OpenCity mirrors say "Other (Public Domain)" / "No License
   Provided"; Dataful says nothing; NDAP's own terms page 404s. *Action: for anything we
   publish, cite the original government table, not the mirror, and keep the mirror as
   transport only. Get a lawyer's read on GODL-India attribution requirements before launch.*
6. **Unsourced synthetic data is circulating and being treated as real.** *Action: enforce a
   provenance gate — a dataset is ingestible only if it resolves to a named government table.
   Everything else is labelled synthetic in the UI or excluded.*
